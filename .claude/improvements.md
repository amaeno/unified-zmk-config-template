# skills・サブエージェントの改善メモ

作業中に、skills やサブエージェントが手順どおりに進まなかったことを 1 行ずつ書く。
`/retro` がこれを材料に改善案を出し、ユーザーが承認したものだけを直す。

- 書き方: `- YYYY-MM-DD 対象: 何が起きたか（分かれば、何が足りなかったか）`
- 対象の例: `zmk-build`、`config-reviewer`、`CLAUDE.md`
- 「未対応」に 1 件以上あると、作業の区切りで Stop フック（`.claude/hooks/retro-nudge.py`）が振り返りを促す

## 未対応

- 2026-10-11 zmk-researcher: 改善メモで「zmk-docs は zmk-docs/keymaps/… で docs/ を挟まない」と再指摘。定義の「ZMK の docs/docs/ をそのまま写したもの」が zmk-docs/docs/ と読まれやすい（直下に keymaps/ などが並ぶと明記するとよい）
- 2026-10-11 retro-nudge: 区切りの判定が「未コミットの変更が無い」だけなので、機能の設計を相談している途中（main で、まだ何も編集していない状態）でも発火しうる。main にいて、かつ機能ブランチの作業が終わったときに絞るなど、判定を見直す余地がある
- 2026-10-11 config-reviewer: ZMK の調査用コピー（.zmk-ref/）の存在を知らず、「ローカルに ZMK のソースが無い」として zip_x_scaler の存在を要確認にした → 定義に .zmk-ref/ と、その中のどこを見ればよいかを足すとよい
- 2026-10-11 add-feature: ビルドとレビューを並行させたため、レビュー役がビルド成功（＝ラベルが実在する裏付け）を知らずに要確認を出した → ビルドを先に済ませ、結果をレビューの依頼文に含めると手順に明記するとよい
- 2026-10-11 lint-keymap: input-processors や keymap が参照する ZMK 標準のラベル（&zip_* など）が実在するかは調べていない（レビュー役の改善メモ）→ .zmk-ref/ があれば dts の定義と照合する検査を足す案
