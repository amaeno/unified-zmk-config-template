# 振り返りと改善提案

skills とサブエージェントは、使って困ったところを直すことでしか良くなりません。この振り返りは、その「困ったところ」を集めて、小さく確実に直すためのものです。**提案するところまでが自分の仕事で、直すかどうかはユーザーが決めます。**

## 1. 材料を集める

- `.claude/improvements.md` の「未対応」
- このセッションの出来事: skill やサブエージェントの失敗・やり直し、ユーザーからの訂正、想定より長くかかった作業、書いてあるのに使われなかった手順、逆に毎回その場で補っていた前提
- 必要なら対象の定義を読む（`.claude/skills/*/SKILL.md`、`.claude/agents/*.md`、`CLAUDE.md`）

## 2. 提案する（まだ直さない）

効果の大きい順に最大 5 件。1 件ずつ次の形で出します。

```
1. 対象: .claude/agents/config-reviewer.md
   変えること: 観点に「〜」を足す（差分の要点を 1〜2 行）
   理由: 2026-10-12 のメモ「〜」／このセッションで〜が起きた
   種類: 手順の追加・修正 / 前提の明記 / モデルの見直し / 不要な手順の削除
```

- **モデルの見直し**の目安: haiku で失敗や手戻りが 2 回以上続いたら sonnet へ。sonnet で毎回同じ定型作業しかしていなければ haiku へ。CLAUDE.md の「エージェントとモデル」の方針に沿う
- 前提が足りないだけなら、モデルを上げる前に前提を書き足す案を優先する（低いモデルでも前提が明確なら十分に動くため）
- 提案が無ければ「改善案はありません」と 1 行で返す。メモが残っていて直す必要が無いと判断したら、理由を添えて「見送り」に移す案として出す

最後に「どれを適用しますか？（番号で。全部・なしも可）」と聞いて止まります。

## 3. 承認されたものだけ適用する

- 変更は小さく保つ。skill を大きく書き直すときは、Anthropic の skill-creator の書き方（説明文に「いつ使うか」を書く、命令より理由を書く、本文は簡潔に）に従う
- 適用したら `python3 scripts/gen-docs.py` を実行する（資料の AI ツール一覧が frontmatter から作られているため）。skills やエージェントの使い方・流れが変わるときは、`docs/workflow.html` の「AI と進めるとき」（`id="ai"`）の手書き部分も必ず直す
- `.claude/improvements.md` で、対応したメモを「対応済み」へ移し、日付と何をしたかを添える。見送ったものも理由を添えて「対応済み」へ移す
- コミットはユーザーの了承を得てから行う（日本語で、`docs/` 系の変更として）

## やらないこと

- 承認されていない定義を書き換えない
- CLAUDE.md のルール（エージェントの上限、push 禁止など）を緩める提案を、具体的な理由なしにしない
