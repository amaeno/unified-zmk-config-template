# 機能の追加・変更の流れ

やりたいこと: $ARGUMENTS

この流れの目的は、**実機に書き込む前に誤りを潰し、書き込んだ版にいつでも戻れるようにする**ことです。書き込みと動作確認はユーザーにしかできないので、その前までを確実に仕上げます。

## 0. 本当にファイルの変更が要るか

- キー割り当て・レイヤーの使い分けだけなら ZMK Studio で済む（キー割り当ての正本は Studio）。そう伝えて終える（`docs/workflow.html` の `id="decide"`）
- 機能に特定のキーへの割り当てが要るとき（例: `&lt`）は、ファイルの初期値を変えたうえで、手順 6 で「Studio で保存済みなら、Studio でも同じ割り当てをしてほしい」と伝える（Studio で保存した割り当てがファイルより優先されるため）
- 新しいモジュール、複数ファイルにまたがる変更、挙動の設計に選択肢があるものは、先に**方針案と決めてほしい点**をユーザーに出し、合意してから進める（ユーザーは方針を先に確かめたい人なので）

## 1. 調べる

- 触るファイルと現在値: `docs/settings.html` の `id="map"`
- 触るファイルが `docs/known-issues.html` に載っていないか（消すとビルドが壊れる箇所がある）
- ZMK の仕様が絡むなら **zmk-researcher** に聞く。記憶で書かない（版で書き方が変わるため）
- キーの位置は `docs/keymap.html` の `id="positions"` のテキスト版

## 2. ブランチを切る

```bash
git switch -c feature/<名前> main   # 不具合なら fix/、ビルド環境なら build/、資料なら docs/
```

未コミットの変更が残っていたら、切り替える前にユーザーに確認する。

## 3. 編集する

- 変更は最小にする。周りの書き方とコメントの言語（日本語）に合わせる
- 左右どちらのファイルかを取り違えない（右がセントラル。キーマップと input-processors は右）

## 4. 確かめる

1. `python3 scripts/lint-keymap.py`
2. `python3 scripts/gen-docs.py`（資料の生成部分を更新）
3. `/zmk-build <ターゲット>` — 書き込む側のターゲットをビルドする（`docs/workflow.html` の `id="flash"` の表）。ビルドログはこの skill が要約して返す
4. **config-reviewer** に変更を見せる。**ビルドが済んでから**頼み、ビルドの結果（成否と警告の要点）を依頼文に含める（レビュー役はビルドしないので、結果を知らないと、ビルドで裏付けられた点まで「要確認」にしてしまうため）。要修正なら直して 1 からやり直す
5. **資料を必ず更新する。** 仕様（挙動・設定値・キー割り当て・手順）が変わったら、生成部分だけでなく手書きの説明も直す。**docs-sync** に頼むか、小さな修正なら update-docs skill に従って自分で直す（資料は事実の正本なので、実態とずれると次の作業を誤らせるため）

調査は編集と並行してよいが、レビューは編集とビルドが終わってから走らせる。サブエージェントは同時 5 本・この流れ全体で延べ 10 本まで（CLAUDE.md）。

## 5. コミットする

日本語で、何を・なぜ。更新した資料も同じコミットに含める。資料の更新が済んでいない変更はコミットしない。

## 6. 実機での確認を頼む

ユーザーに次を伝えて、作業をいったん止める。

- 書き込むファイルと側（例: 「右に `firmware/sosho_R_trackpad.uf2`」）
- 確かめてほしい動作と、うまくいかないときに見る場所（`docs/workflow.html` の `id="trouble"`）
- 「確認できたら教えてください。main に取り込んでタグを打ちます」

`main` への取り込み（`git merge --no-ff`）とタグ（`fw-YYYY-MM-DD`）は、ユーザーが確認したと言ってから行う（`docs/workflow.html` の `id="merge"`）。

## 振り返り

この流れのどこかで手順どおりに進まなかったら（失敗、遠回り、ユーザーからの訂正、エージェントの力不足）、その場で `.claude/improvements.md` の「未対応」に 1 行書く。サブエージェントや `/zmk-build` の報告に「改善メモ」があれば、それも転記する。
