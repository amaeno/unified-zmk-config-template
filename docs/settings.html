「書き込む側」の考え方は 開発フロー › 書き込み にあります。キーマップは右だけが処理するので、キーマップ関係は右だけで済みます。

スクロール

スクロールのしかたは 3 通りあり、それぞれ調整する場所が違います。

スクロールのしかた量を変える場所
エンコーダを回す（&ec_ms_l / &ec_ms_r）1 回の発火で 1 ノッチ。発火の回数は triggers-per-rotation（いま 24 、1 回転あたり）で決まる。音量など他のエンコーダ操作も同じ値を使う。細かい量は OS のスクロール設定で調整する
ポインタの動きをスクロールに変える（zip_xy_to_scroll_mapper）右の overlay の input-processors で、前に zip_xy_scaler を置いて速さを変える。この機体では、L4 scroll のあいだの左トラックボールがこの方法でスクロールになる（下の注記）
キーにスクロールを割り当てる（&msc）いまのファイルの割り当てでは使っていない。使うときの最大の速さは SCRL_UP などの値（ZMK の既定）、加速は config/sosho.keymap の &msc の time-to-max-speed-ms（いま 0 ）・acceleration-exponent（いま 0 ）

左トラックボールを縦スクロールにする（L4 scroll）: L0 の 0 番（Tab）を長押し（既定で約 200 ms）すると L4 scroll に入り、そのあいだだけ左のトラックボールが縦スクロールになります。タップなら通常の Tab です。設定は sosho_R_trackpad.overlay の trackball_split_listener の子ノード scroller（layers = <4>）にあります。書き込むのは右（sosho_R_trackpad）だけです。input-processors（いまの値は ポインタ の表の「L4 scroll のとき」）は、次の役割のものをこの順に並べています。

  1. &zip_x_scaler 0 1 — 横の動きを捨てる
  2. &zip_xy_scaler 分子 分母（1 つ以上） — 動きを縮めて、スクロールの速さを決める
  3. &zip_xy_to_scroll_mapper — スクロールに変える

速さは zip_xy_scaler の「分母 ÷ 分子」の積で決まります。いまは 32 カウントで 1 ノッチで、大きくするほど遅くなります。向きが逆なら、mapper の前に <&zip_xy_transform INPUT_TRANSFORM_Y_INVERT> を足します。スクロールに切り替わることは実機で確認済みです。横の動きが本当に捨てられているかと、速さの調整は、もっさり感の調査のときに見直します。

ポインタ

ポインタの動きは、右の overlay にあるリスナー（*_listener）を通って PC に届きます。リスナーに input-processors を書くと、速さや向きを加工できます。左の入力も右のリスナー（*_split_listener）を通るので、左のトラックボールの調整も右の overlay に書きます（仕組み）。

よく使う input-processors

書き方効果
<&zip_xy_scaler 2 1>速さを 分子 / 分母 倍にする。2 1 なら 2 倍、1 3 なら 1/3
<&zip_xy_to_scroll_mapper>ポインタの動きをスクロールに変える

たとえば左のトラックボールを半分の速さにするなら、この機体の右の overlay（sosho_R_trackpad.overlay）の trackball_split_listener に次の 1 行を足して、右に書き込みます。

&trackball_split_listener {
    status = "okay";
    input-processors = <&zip_xy_scaler 1 2>;
};

子ノード（レイヤー別の上書き）があるときの注意: リスナーの子ノード（例: scroller）の layers に当てはまるあいだは、親の input-processors は使われず、子の設定に置き換わります（子に process-next を付けた場合を除く）。この機体では、L4 のあいだは上の半分の速さの例のような親への変更が効きません。L4 のあいだの動きを変えたいときは、子ノード scroller の input-processors を直します（スクロール）。

ほかの input-processors は ZMK の公式ドキュメント（Input Processors）にあります。トラックパッドの上下左右の向きは、デバイス側の invert-x / invert-y でも変えられます（ハードウェア › ポインティングデバイス）。

エンコーダ

  • steps（1 回転のパルス数）: 96
  • triggers-per-rotation（1 回転で割り当てが動く回数）: 24

1 クリックで 2 ノッチ動かしたいなら triggers-per-rotation を 2 倍にします。値は左右のエンコーダで共通です。速く回したときに取りこぼす場合は、Kconfig の ZMK_BEHAVIORS_QUEUE_SIZE（下の一覧）を見直します。

Bluetooth の接続

Bluetooth の接続は 2 本あります。設定が効くのは、右と PC の接続だけです。

接続接続条件を決めるものいまの値
右（セントラル）と PC右の *.conf の BT_PERIPHERAL_PREF_* を、右が接続後に PC へ要求する。最終的に決めるのは PC 11.25〜15 ms（MIN_INT=9 ／ MAX_INT=12）
左（ペリフェラル）と右右が接続するときに決める（ZMK の既定で 7.5 ms・latency 30）。左の BT_PERIPHERAL_PREF_* は使われないZMK の既定のまま

根拠は ZMK リファレンス › このリポジトリで確かめた仕様 にあります。左の conf に残っている「フリーズ対策」の 3 行は本家由来で、効いていません。

Mac には Apple の規定に合う値を要求する: ZMK の既定（7.5〜15 ms）のままだと、Mac で全部の入力が 1 テンポ遅れて見えました（2026-10-12）。そこで右の要求を、Apple の規定（QA1931）に合う値（上の表。*_INT の単位は 1.25 ms）に変えています。規定の要点は次のとおりです。

  • 下限は 15 ms 以上（15 ms の倍数）が原則。ただし HID（キーボードやマウス）なら 11.25 ms まで受け付けることがある
  • 上限は「下限 + 15 ms」以上。ただし上限 15 ms は認められる
  • 15 ms 固定（12 / 12）を要求すると、30 ms に広げる Apple の機器がある

Mac で反応が遅いと感じたら、まず右を USB ケーブルでつないで比べます。USB で遅れが消えるなら、原因は右と PC の Bluetooth の接続です。
