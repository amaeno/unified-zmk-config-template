このリポジトリで確かめた仕様

作業の中で、使っている版のソースやドキュメントで確かめたことです（基準: ZMK 4dd95d7 ）。出典は .zmk-ref/ の中のパスです。版を上げたら、関係するものは確かめ直します。

  • エンコーダの割り当ては「時計回り、反時計回り」の順

    sensor-bindings の第 1 引数が時計回り。出典: zmk-docs/keymaps/behaviors/sensor-rotate.md

  • 割り当ての無いレイヤーでは、下のレイヤーのエンコーダ割り当てが効く

    有効なレイヤーを上から見て、割り当てのある最初のものを使う。出典: zmk-app/src/keymap.c の zmk_keymap_sensor_event

  • エンコーダのスクロールは 1 回の発火で 1 ノッチ

    zmk_encoder は値の向きだけを使い、量をそろえる。そのため ZMK_POINTING_DEFAULT_SCRL_VAL は効かない（&msc の最大速度にだけ効く。このキーマップでは定義していないので ZMK の既定値）。出典: zmk_encoder/src/behavior_encoder_mouse_scroll.c、zmk-app/include/dt-bindings/zmk/pointing.h

  • Studio で保存した割り当てはファイルより優先される

    ファイル側に戻すには「Restore Stock Settings」。出典: zmk-docs/features/studio.md

  • Studio はエンコーダの割り当てとコンボを扱わない

    Studio の通信の処理に、どちらも出てこない。出典: zmk-app/src/studio/

  • Studio が有効なときだけ、予約レイヤーも数えられる

    Studio を外すと scroll などの予約レイヤーは無いことになり、呼び出すキーが効かなくなる。出典: zmk-app/src/studio/Kconfig、zmk-app/include/zmk/keymap.h

  • リスナーの子ノードで、レイヤーごとに input-processors を上書きできる

    layers に当てはまるあいだは親の設定の代わりに使われる（process-next を付けたときを除く）。出典: zmk-docs/keymaps/input-processors/usage.md、zmk-app/src/pointing/input_listener.c

  • zip_xy_scaler の分母は 16 以下が推奨

    もっと縮めたいときは段を重ねる（端数はそれぞれ持ち越される）。出典: zmk-docs/keymaps/input-processors/scaler.md

  • トラックボールの CPI はキーで切り替えられない

    cpi は 200〜3200 の 200 刻みで、起動時に設定される。出典: zmk-pmw3610-driver/src/pmw3610.c、zmk-pmw3610-driver/dts/bindings/pixart,pmw3610-alt.yml

  • EC11 の resolution は steps があると使われない

    出典: zmk-app/module/drivers/sensor/ec11/ec11.c

  • コンボの誤爆を防ぐ設定がある

    require-prior-idle-ms（ms）、layers、slow-release。出典: zmk-app/dts/bindings/zmk,combos.yaml、zmk-app/src/combo.c

  • 状態表示 LED の色

    接続状態は 青 = つながっている、黄 = 待ち受け、赤 = 切れている。出典: zmk-rgbled-widget/README.md

  • 左右間の Bluetooth の接続条件は右が決め、左の BT_PERIPHERAL_PREF_* は使われない

    右は接続するときに ZMK_SPLIT_BLE_PREF_INT（既定 6 = 7.5 ms）・ZMK_SPLIT_BLE_PREF_LATENCY（既定 30）で接続し、その後は変えない。左は BT_GAP_AUTO_UPDATE_CONN_PARAMS が切ってあり、自分から変更を要求しない（左のビルドの .config でも確認）。出典: zmk-app/src/split/bluetooth/central.c（bt_conn_le_create）、zmk-app/src/split/bluetooth/Kconfig

  • 右と PC の接続条件は、Zephyr が右の BT_PERIPHERAL_PREF_* で PC に要求する

    ZMK 自身は要求を出さない（ZMK Studio の接続中に latency を変える場合を除く。右は latency 0 なのでこれも起きない）。右のビルドの .config で BT_GAP_AUTO_UPDATE_CONN_PARAMS=y を確認。最終的に決めるのは PC で、Mac に合う値は Apple の規定による（設定項目 › Bluetooth の接続。Mac が実際に何 ms を選んでいるかは未確認）。出典: zmk-app/src/ble.c、zmk-app/src/studio/gatt_rpc_transport.c、zmk-app/Kconfig

  • Bluetooth で送りきれないマウスのレポートは溜まり、遅れが積み上がる

    レポートは 1 つずつ送られ、送れない分は待ち行列（ZMK_BLE_MOUSE_REPORT_QUEUE_SIZE、既定 20）に溜まる。まとめて送る仕組みは無い。満杯になると、入力の処理が送信の空きを最大 100 ms 待つ。出典: zmk-app/src/hog.c の zmk_hog_send_mouse_report

  • リスナーは sync のたびにマウスのレポートを送る（動きが 0 でも送る）

    input-processors で値が 0 になっても送るので、スクロールに変えているあいだも、トラックボールの報告の回数だけレポートが出る。出典: zmk-app/src/pointing/input_listener.c の input_handler

  • 送信が詰まると、キーとエンコーダの処理まで止まる

    トラックパッドのドライバは Zephyr 本体のもので、入力を「空くまで待つ」（K_FOREVER）で渡す。この処理は Zephyr の共有の作業スレッド（system workqueue）で動き、キーの読み取り（kscan）とエンコーダ（EC11_TRIGGER_GLOBAL_THREAD）も同じスレッドを使う。出典: zephyr/drivers/input/input_pinnacle.c、zmk-app/module/drivers/kscan/kscan_gpio_matrix.c、zmk-app/module/drivers/sensor/ec11/ec11_trigger.c

  • &zip_ble_report_rate_limit は動きを捨てずに次のレポートに足す

    引数の ms より短い間隔で来た X・Y の値は、送らずに溜めておき、次に通すイベントに足す。溜めたまま引数の 2 倍より長く止まると、その分は捨てる。limit-ble-only 付きなので、出力先が Bluetooth のときだけ効く。出典: zmk-input-processor-report-rate-limit/src/pointing/input_processor_report_rate_limit.c

  • ZMK は USB 給電中は deep sleep に入らない（左も同じ）

    活動の管理が USB 給電の有無を見て、給電中は deep sleep を避ける（CONFIG_USB_DEVICE_STACK が有効なとき）。左には ZMK_USB の設定が無いが、XIAO のボード定義が USB シリアル（CDC ACM）のために CONFIG_USB_DEVICE_STACK=y にしていて、ZMK の src/usb.c が入る（左のビルドの .config で確認）。出典: zmk-app/src/activity.c の is_usb_power_present()

  • ZMK の電池の測定は IDLE（操作が無くて 30 秒）で止まる

    止まっている間は電圧が更新されない。充電表示はこのため、完了の判定のときに自分で電圧を測る。出典: zmk-app/src/battery.c

  • zmk-rgbled-widget には充電の表示が無い

    本家の README で確認（2026-10-12）。出典: zmk-rgbled-widget/README.md

  • BQ25101 の CHG は、電源をつないでから最初の充電の間だけ Low

    継ぎ足しの充電では Low に戻らない。安全タイマー（10 時間）で止まったときは High になる。出典: TI BQ25101 データシート 8.3.2・8.3.9（ハードウェア › 充電まわり）

  • CONFIG_NFCT_PINS_AS_GPIOS は非推奨

    後継は devicetree の &uicr { nfct-pins-as-gpios; }（このリポジトリは 2026-10-12 に移行済み）。出典: Zephyr の soc/nordic/Kconfig（.zmk-ref/ には写していない）
