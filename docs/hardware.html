全体の構成

  • 左右それぞれに Seeed XIAO nRF52840 が載っていて、左右は Bluetooth で繋がります。
  • 右がセントラルです。PC と Bluetooth（または USB）で繋がり、キーマップの処理もここで行います。ZMK Studio で USB 接続するのも右です。
  • 左はペリフェラルです。キーが押された位置、エンコーダの回転、ポインタの動きを右へ送るだけで、キーマップは持ちません。
  • 状態表示の RGB LED は、ビルド時に一緒に指定する rgbled_adapter シールドと、zmk-rgbled-widget モジュールで動かします。使う LED は、sosho.dtsi の aliases（led-red = led0 など）で XIAO 基板上の LED に割り当てています。電池残量と接続状態に加えて、USB でつないでいるときは充電の状態も出します（電池と充電）。

ピンの表記: P0.02 は nRF52840 のピン名（ポート 0 の 2 番）です。横の D0 などは XIAO の基板に印刷されている名前です。D0〜D10 以外のピンは、XIAO nRF52840 Plus で増えた裏面のピンです。

左の入力が右に届くまで

左のトラックボールの動きは、左で読み取ってから Bluetooth で右へ送られ、右で加工されて PC に届きます。速さや向きを変える input-processors は、右の overlay の受け口（*_split_listener）に書きます。

  1. 左で読む。 トラックボール（trackball）が動きを読み取ります。

  2. 右へ送る。 左の overlay の trackball_split（zmk,input-split）が、Bluetooth で右へ送ります。

  3. 右で受ける。 右の trackball_split が同じ番号（reg）で受け取り、trackball_split_listener に渡します。

  4. 加工して PC へ。 リスナーの input-processors で速さ・向き・スクロール化を加工し、Bluetooth で送りきれる回数に間引いてから、PC に送ります（設定項目 › 送りきれないレポートが溜まるとき）。

キーの押下とエンコーダの回転も同じように右へ送られ、キーマップは右だけが処理します。そのため、キーマップやコンボを変えたときは右に書き込むだけで済みます。

電池と充電

左右それぞれが、自分の電池の充電状態を状態表示の LED に出します（src/charging_led.c）。充電そのものの動きには触りません。XIAO 基板上の赤い充電 LED もそのまま点きます。

LED の表示

状態表示意味
充電中黄をゆっくりフェード（呼吸のように明るくなり、暗くなる。3 秒で 1 往復）充電 IC が充電している
完了緑を点灯（USB を抜くまで）充電が止まり、電池電圧が 4000 mV 以上
要確認赤を同じようにフェード充電が止まっているのに、電池電圧が 4000 mV 未満（または測れない）。電池・温度・安全タイマーの打ち切りなどを疑う
USB なし何もしない従来の表示（電池残量・接続状態）のまま
  • 判定の仕組み: 充電 IC の CHG 信号（P0.17。充電中は Low）と、nRF52840 の USB 給電の検出（POWER の USBREGSTATUS.VBUSDETECT）を 1 秒ごとに読み、同じ状態が 3 秒続いたら確定します。
  • 完了と要確認の分け方: CHG が High になったら電池電圧を測ります。充電が止まっている間は 60 秒ごとに測り直します。電池残量（%）で判定しないのは、充電中は電圧が高く出て % が早く 100% になるためです。
  • 電圧を自分で測る理由: ZMK の電池の測定は、操作が無いまま 30 秒で止まります。このモジュールは完了の判定のときに自分で測ります（ZMK の測定と同じ低優先度のキューで動かし、測定が重ならないようにしています）。
  • deep sleep: ZMK は USB から給電されている間は deep sleep に入らないので、充電中に表示が消えることはありません。左も同じです（ZMK リファレンス › 確かめた仕様）。deep sleep に入るときはフェードを止め（作業の終わりを待ってから）、LED を消します。
  • フェードの仕組み: &pwm1 を LED の赤（P0.26）と緑（P0.30）に割り当て、周期 1 ms（1 kHz）の PWM で明るさを変えます（LED は Low で点くので反転）。1 往復の前半で明るく、後半で暗くし、端はなめらかにつなぎます。いちばん暗いときも見た目の明るさで 20 % を残します（目の感じ方に合わせて、LED に流す時間の割合はその 2 乗の 4 % です）。フェード中は 20 ms ごと、それ以外は 1 秒ごとに動きます。PWM が動くのはフェード中（USB 給電中）だけです。
  • 黄の色味: XIAO の緑の LED は抵抗が 10 kΩ で、赤・青の 2.2 kΩ よりずっと暗いため（回路図の R7・R4・R3）、赤と緑を同じだけ点けるとオレンジに見えます（widget の「黄」もそうです）。フェードの黄は、赤を緑の 50 % に弱めて黄に寄せています。上げるとオレンジ寄りで明るく、下げると緑寄りで暗くなります。
  • widget との受け渡し: LED の赤・緑のピンは、widget の GPIO（gpio-leds）と PWM の両方が使います。デューティが 0 % か 100 % のチャンネルでは、Zephyr の nRF の PWM ドライバが PWM を止めて GPIO の出力に任せるので（drivers/pwm/pwm_nrfx.c のコメント）、フェードを止めれば widget の点け消しがそのまま効きます。widget が何かを表示しようとしたとき（表示待ちの列に項目がある、または LED のピンの出力が点灯になっている）は、フェードを止めて LED を widget に返します。そのため充電中でも、接続先を切り替えたときの点滅などはふだんどおり見えます。デューティを 99 % で頭打ちにしているのは、100 % にするとドライバが出力を点灯に書き換え、widget の表示と見分けられなくなるためです。
  • 設定: フェードの速さ・暗いときの明るさ・黄の色味と、完了とみなす電圧は Kconfig で変えます（設定項目 › 充電表示）。

zmk-rgbled-widget の内部に頼っています。 src/widget.c の大域変数 led_msgq・led_layer_color・led_current_color と struct blink_item の並びを使っています。widget の版を上げるときは、これらが変わっていないか確かめます（開発フロー › ZMK の版を上げる）。起動時に led_msgq の項目の大きさが合わないと、ログにエラーを出して充電の表示は動きません。

充電まわりのハードウェア

出典: XIAO nRF52840 v1.1 の回路図、TI BQ25101 データシート、Seeed Wiki と 充電の注意。

  • 充電 IC は BQ25101

    定電流で充電したあと、4.2 V（誤差 1%）の定電圧で充電し、電流が小さくなったら終えます。終えたあと 4.1 V（4.2 V の 100 mV 下）まで下がったら継ぎ足します。10 時間の安全タイマーで打ち切ります（データシート）。

  • CHG は「電源をつないでから最初の充電の間だけ」Low

    継ぎ足しの充電では Low に戻りません。安全タイマーで止まったときは High になります（データシート 8.3.2・8.3.9）。このため「完了」は CHG が High になったうえで電圧でも確かめています。

  • CHG は赤い充電 LED と P0.17 につながる

    XIAO の赤い充電 LED（3V3 から 2.2 kΩ）と P0.17 が同じ信号です。赤い LED は充電中に点き、完了で消えます（回路図）。

  • 状態表示 LED の明るさは色ごとに違う

    緑の LED は抵抗が 10 kΩ、赤・青は 2.2 kΩ で、緑がとても暗いです（回路図の R7・R4・R3）。

  • ボード定義の &pwm0 は P0.17（CHG の線）に出力する

    PWM のドライバを入れるとマイコンが CHG の線を駆動してしまうので、sosho.dtsi で &pwm0 とボードの pwmleds を無効にしています。出典: .zmk-ref/zephyr-xiao_ble/xiao_ble-pinctrl.dtsi の pwm0_default、xiao_ble_common.dtsi

  • USB 給電中は電池が切り離される

    3.3 V のレギュレータには VBUS からダイオード経由で給電され、電池は P-MOSFET で切り離されます（回路図の Q1・D1）。打っている最中でも充電の終了判定が狂いません。

  • 電池の温度監視は無効

    TS 端子は 10 kΩ で GND に固定されています（回路図の注記「Disable Temp sense function」）。そのため、暑い場所や 0 ℃ 以下では充電 IC が自分では止まりません。

  • 充電電流は約 50 mA

    ISET の抵抗 2.7 kΩ（固定）と、P0.13 につながるもう 1 本の 2.7 kΩ で決まります。P0.13 を Low にすると約 100 mA、触らなければ（ハイインピーダンス）約 50 mA です。ZMK は P0.13 を使っていないので約 50 mA です（回路図と Seeed Wiki）。

  • 電池電圧は P0.31 で測る

    VBAT から 1 MΩ / 510 kΩ の分圧で、下側は P0.14 です。Seeed は「充電中に P0.14 を High にすると P0.31 が 3.6 V に達して壊れるおそれ」と注意しています。ZMK のボード定義は P0.14 をオープンドレインのアクティブ Low にしていて、測るときだけ Low にし、ふだんは離します（High には駆動しません）。出典: .zmk-ref/zmk-app/boards/seeed/xiao_ble/xiao_ble_zmk.dts、battery_voltage_divider.c

つなぎっぱなしで過充電にならないか

4.2 V を超えて充電され続けることはありません（上の電圧制御・終了・安全タイマーのため）。つなぎっぱなしの影響は寿命の問題です。満充電の近く（4.1〜4.2 V）に張り付くので、容量の減りや膨らみが早まります（熱で悪化します）。完了したら外す運用がよいです。電池側の保護回路（過充電で切る保護基板）の有無は手元の電池によります。
