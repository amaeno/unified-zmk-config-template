キーマップ

config/sosho.keymap の中身を図にしたものです。レイヤーごとの割り当て、コンボで使うキー位置番号、エンコーダの動きをまとめています。

ZMK Studio で変えた割り当ては、この図に出ません。 この図はファイルの内容です。Studio で変更した内容はキーボード側に保存され、ファイルより優先されます（開発フロー › ビルドが要るか）。

コンボ

2 つ以上のキーを同時に押すと、別の動作になる設定です。判定時間（timeout-ms）の間に押せば同時とみなされます。

コンボキー位置同時に押すキー（L0）動作判定時間
combo_LCLK19 20J + K左クリック &mkp LCLK50 ms
combo_RCLK20 21K + L右クリック &mkp RCLK50 ms
combo_MCLK19 21J + L中クリック &mkp MCLK90 ms

自動生成 · 元: config/sosho.keymap

増やすときは config/sosho.keymap の combos に同じ形で足します。位置は キー位置番号 で調べ、足したら python3 scripts/lint-keymap.py で範囲外や重複がないか確かめます。

combo_名前 {
    timeout-ms = <50>;
    key-positions = <19 20>;
    bindings = <&mkp LCLK>;
};

エンコーダ

エンコーダの割り当ては、各レイヤーの sensor-bindings に「時計回りのとき」「反時計回りのとき」の順で書きます（上の図の下にある一覧）。逆に感じるときは、2 つの引数を入れ替えます。

  • 割り当ての無いレイヤーでは、下のレイヤーの割り当てが効きます。 ZMK は有効なレイヤーを上から見ていき、割り当てのある最初のレイヤーを使います（ZMK 本体の zmk_keymap_sensor_event の動き）。
  • スクロールには zmk_encoder モジュールの &ec_ms_l / &ec_ms_r を使っています。1 回の発火で 1 ノッチぶんのスクロールを送ります。
  • 音量など普通のキーを送るときは、ZMK 標準の &inc_dec_kp を使います（L2 の左エンコーダ）。

なぜ専用モジュールなのか: 以前（verB まで）は ZMK 標準の zmk,behavior-sensor-rotate-var と &msc でスクロールさせていましたが、1 回のスクロールごとに「押す」「離す」の 2 つのイベントが出ます。負荷が高いと「離す」が落ちて、スクロールし続ける問題がありました。verB2 で入った zmk_encoder は 1 つのイベントで完結するので、この問題が起きません（本家の memo.md より）。
